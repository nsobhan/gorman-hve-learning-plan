Standardizing Gorman Manufacturing with HVE Core

A hands-on learning plan for Hypervelocity Engineering (HVE) Core, built around one fictional manufacturer. Learners fix a real KPI problem with HVE's agents, instructions and skills. 18 modules, copy-paste prompts, a reference solution for each step, and a demo script you can run for customers.

“AI carries the rules, humans keep the judgment.”

The problem

One shift, three plants, three answers

Gorman’s plants each calculate OEE (Overall Equipment Effectiveness) with their own script. Here is Line 1, shift A on 2 Nov 2026, run through each plant’s code:

Detroit · DET69.6%Divides performance by planned time, not run time
Monterrey · MTY81.2%Leaves out quality, then crashes on a zero-production shift
Pune · PNQ72.9%Rounds each factor before multiplying
Standard GMS-OPS-00777.2%A 0.902 × P 0.901 × Q 0.950

The scripts also hold fake hard-coded credentials and a SQL injection risk, put there on purpose so the security modules have something to find. Gorman, its plants, data and credentials are all fictional.

The core method

RPI: research before code

When the AI knows it isn’t allowed to implement yet, it stops writing plausible code and starts finding verified facts. Each phase writes an artifact, so you can clear the chat between phases without losing context.

Phase 1

Research

/rpi-research

Finds every way the plant scripts differ from the standard, with file references.

.copilot-tracking/research/
Phase 2

Plan

/rpi-plan critique=standard

Task-level plan plus an independent critique: the evidence Gorman’s change policy asks for.

.copilot-tracking/plans/
Phase 3

Implement

/rpi-implement

Builds the shared gorman_oee library by following the plan, and logs every change.

.copilot-tracking/changes/
Phase 4

Review

/rpi-review

Checks the changes against the plan and sends each follow-up to the right phase.

.copilot-tracking/reviews/

Module 07 then runs all four phases in one session with RPI Agent to onboard a fourth plant, Ostrava, which exports JSON instead of CSV.

For customer meetings

Running it as a demo

30-minute track

  1. The problem (4 min): run the three plant scripts and show three answers.
  2. AI carries the rules (5 min): ask the same question before and after adding Gorman’s instruction files.
  3. Research before code (10 min): /rpi-research live, then open its bug table.
  4. One answer (6 min): tests pass and 77.2% comes out of all four formats.
  5. Humans keep the judgment (5 min): the Gorman KPI Steward agent blocks a risky master-data change.

Add for the 60-minute track

  • Plan with critique (Module 04)
  • Security Reviewer finds the planted secrets (Module 09)
  • Root cause analysis: a Line 3 OEE drop blamed on a new crew turns out to be a master-data change made before the new die arrived (Module 12)
  • /gorman-shift-report, a custom slash command (Module 13)

Get going in 30 minutes

Install the hve-core plugin in VS Code or GitHub Copilot CLI, then copy the sample project into your own workspace and follow Module 00.

cp -R gorman-sample-project ~/gorman-mes && cd ~/gorman-mes && git init && git add . && git commit -m "Baseline"

Run the commands from inside the hve-core course folder. Needs VS Code or Copilot CLI, a GitHub Copilot subscription, Git and Python 3.11+.
